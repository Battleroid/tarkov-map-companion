# Tarkov Map Companion

用于《逃离塔科夫》的第二屏地图，显示你在哪里、面朝哪个方向，以及如何走到你选定的撤离点。

它的原理是监视你的截图文件夹。你每截一张图，塔科夫都会把位置和镜头朝向写进截图的*文件名*里，所以按下截图键就能刷新地图。

![The app showing Shoreline with an exit selected](docs/screenshot-dark.png)

## 关于本分支

本分支是 [`Battleroid/tarkov-map-companion`](https://github.com/Battleroid/tarkov-map-companion) 的自我改进版——那是 Battleroid 的原始项目，采用 MIT 协议，至今仍是这里一切的基础。本 README 其余部分沿用其原文，保持原样，只在本分支有差异的地方做了修订；想了解本分支没有碰过的功能，原始仓库才是该去的地方。

本分支新增或改动的内容：

- **全面简体中文化。** 每个控件、面板、偏好设置、楼层名、图层标签和撤离条件都已翻译，并在**设置**里提供语言开关。全新安装默认中文；已有的 `settings.json` 会保留它原本指定的语言。
- **修正了随附的撤离点数据。** 构建列表时会把内置 tarkov.dev 数据里的三处缺陷规范化，让撤离点列表按本来的样子呈现。见[数据来源](#where-the-data-comes-from)。
- **局域网同步（WebSync）。** 选择开启后，把地图的只读镜像通过你自己的网络提供给平板或手机，附带一个可扫描的二维码，每个请求都要带令牌。详见下文**在平板上，通过局域网**。
- **设置重建为分类栏。** 原本十三个堆叠的区块收成了六个页面，外加一个专门的**局域网同步**页，于是对话框不再是一条长长的滚动条，而成了一组分类。

本分支的已知缺口，都是有意为之并记录在 `docs/` 里：撤离面板 OCR 仍然只匹配英文撤离点名称，所以在中文游戏客户端上**识别撤离点**不起任何作用；WebSync 的浏览器页面只有简体中文，无论桌面端设成什么语言。见*功能*一节末尾的**已知问题**。

## 这不是作弊

本程序从不读取游戏内存、不挂钩进程、不注入任何东西、不修改游戏文件，也不以任何方式和游戏通信。它所知道的一切都来自游戏自己写到你磁盘上的文件，而且只是读取这些文件：

- 截图的**文件名**，用来确定你的位置和朝向；
- 可选的**图片**，用来读取你屏幕上已经出现的撤离点列表；
- 可选的**日志**，即塔科夫运行期间写下的日志，用来判断正在加载哪张地图。

你自己没有截下来的东西它显示不出来，其他玩家它也看不到。

日志是三者里最新的一个，也是唯一不是由你按键产生的，所以默认关闭，并在设置里有自己的开关。它的用途很窄：游戏写明即将加载哪张地图的那一行，以及你获得操作权限的那一行。它是塔科夫文件夹里的一个纯文本文件，你可以用记事本打开，里面没有任何关于别人位置的内容，也不会被写回任何东西。

**局域网同步**是这里唯一会打开网络端口的功能，所以值得说清楚：它默认关闭，只绑定你的局域网，上面的每条路由要么读取桌面窗口已经在显示的内容副本，要么把那份副本再发给你。它没有写入路径——浏览器无法移动你的标记、删除备注或更改设置——而且除了页面本身，每个请求都必须带上生成的令牌。

## 安装

从 [Releases](https://github.com/BlueMess/tarkov-map-companion-self-improv/releases) 下载最新的 **`TarkovMapCompanion-vX.Y.Z-win-x64.exe`** 并运行。

无需安装任何东西。.NET 已经打包进去，地图和撤离点数据也内置在可执行文件里，所以没有网络也能用。

> 可执行文件比上游构建更大——大约 62 MB，而不是 30 MB 左右——因为本分支的局域网同步把 ASP.NET Core 共享框架一起带了进来。

> Windows SmartScreen 会在第一次运行时对未签名的可执行文件发出警告。选择 **更多信息**
> 然后选择 **仍要运行**。每个版本都由 GitHub Actions 根据本仓库里的某个标签构建，所以如果你想弄清这个二进制文件从何而来，可以查看构建日志。

## 功能

**位置和朝向。** 在战局中截一张图，你的标记就会移动。身后的轨迹显示你这一局走过哪里，状态栏显示坐标、朝向、战局内时钟，以及这局已经进行了多久。

**区分战局的轨迹。** 塔科夫的战局内时钟按真实时间的 7 倍走，所以本程序可以靠两个时钟是否同步来判断是不是同一局。昨天的路线绝不会被接到今天的上面，超过当地图战局时长的内容也不会绘制。

**界面语言。** 英文或简体中文，在**设置**里选择，重启后生效。全新安装默认简体中文；已有的 `settings.json` 会保留它原本指定的语言。每个控件、面板和偏好设置都已翻译——529 条字符串，两个文件的键集完全一致——楼层名、图层标签、阵营标签以及撤离条件本身也一样。

专有名词保留拉丁字母——PMC、Scav、AI、Boss 名、商人、Kappa、`ZB-####` 撤离点代码——因为游戏里就是这么显示的。撤离点代码尤其如此，即使中文数据给出了翻译也一样，所以 `ZB-1011` 就显示为 `ZB-1011`，而不是翻译后的建筑名。每条撤离条件都以当前语言画成单独一行，而不是中文叠在英文回显之上。

语言唯一触及不到的，是撤离面板的 OCR，它仍然拿英文撤离点名称来匹配——见下文**已知问题**。

**撤离点及其条件。** 每个撤离点都会显示，并按阵营着色。有条件限制的撤离点在地图上带圆环、在列表里带标记，选中一个就会告诉你它需要什么：

- 峭壁斜坡 — *Red Rebel 冰镐 · 伞绳 · 未装备防弹衣*
- 下水道检修孔 — *未装备背包*
- 宿舍载具撤离点 — *每位玩家 5000 卢布 · 最多 4 名玩家*
- 走私者的船 — *写有代码词 Voron 的纸条*

**只保留你实际拥有的撤离点。** 每局塔科夫给你的撤离点子集都不同，取决于你出生在哪里——海关有 27 个，而某一局可能只给你四个。在撤离点面板里勾选**识别撤离点**，在游戏中调出撤离列表（默认双击 <kbd>O</kbd>）并截一张图：本程序会从图片里读出列表，把游戏没有提供给你的撤离点全部变暗。

撤离点只会变暗，绝不会被隐藏，而且仍然可以点击——这个列表来自字符识别，一次误读的代价应该是一个变暗的标记，而不是一个消失的标记。凡是它读到但无法定位的，都会在面板里列出，而不是悄悄丢掉。识别结果会在一局里不断累积，所以一张在面板刚打开到一半时拍下的截图，只会给已知内容做加法；等到战局结束或你切换地图，整批结果就会被丢弃。它用的是 Windows 自带的 OCR 引擎，所以不会增加下载体积，每张截图耗时约 25 毫秒。

已在 1024x768 到 5120x1440、4:3、5:4、16:9、21:9 和 32:9 各种比例下，对 PMC 和 Scav 两种列表做过验证。分辨率小的画面在读取前会先放大，因为在低于约 900 行时，面板文字会小到整行都看不见，而不是被读错。如果哪次识别出了问题，`--read-exits` 会把每个阶段都打印出来。

**引导线和聚焦模式。** 选一个撤离点，就会画出一条实线指向它，线上标着距离和需要转过的角度（`348 m, 18° right`）。线的颜色由你选。再次点击同一个撤离点就会放开它。打开**聚焦撤离点**后，视图会把你和撤离点一起框进去，随着你靠近而收得更紧，让屏幕上只剩下要紧的东西。关掉它会把你之前的视图原样恢复。

选中一个撤离点会列出它需要什么，而当合作撤离点下面四行条件把别的东西都挤出屏幕时，**隐藏条件**可以把这些收起来。无论如何，列表里的警告标记和地图上的圆环都会保留——隐藏杂乱，不该把“这个撤离点有条件”这件事也一并藏掉。

**路线标记。** 按下**标记路线**，然后按你想去的顺序点击地图——任务目标、值得绕路的藏身处、你把东西丢在哪儿的那个点。每次点击都会留下一个带编号的图钉；再按一次**标记路线**，或按 <kbd>Esc</kbd>，即可结束。箭头沿着路线朝下一个图钉移动，所以不用看数字也能看出路线朝哪边走。引导线按顺序走完整条路线，走完后才重新指向你选的撤离点，因此撤离点可以全程保持选中，而不会碍事。出于同样的原因，聚焦模式框的是下一个标记，而不是撤离点。

走到离某个图钉 50 米以内，它就会功成身退，这个距离可在**设置**里调整。默认情况下，它会先显示为“已到达”一张截图，下一张就消失：这个确认本身就是重点，因为一个凭空消失的图钉会让你搞不清到底是走够近了，还是自己把它放错了位置。另一个选项则在你进入半径的瞬间就移除它。**清除标记**会丢掉整条路线，把引导线交还给撤离点。

**平滑镜头。** 打开**跟随玩家**后，视图会平滑滑到你的新位置，而不是直接跳过去。跳跃会让你失去方位感——每截一张图你都得在地图上重新找到自己——而一个能跟得上的移动则不会。聚焦模式重新取景时也一样，但这从不适用于你自己的平移和缩放，它们始终跟随指针。在**设置**里切换。

平移和缩放**不会**关闭跟随。在两次截图之间查看地图一角，正是你希望被拉回来的时候，而本程序过去却会悄悄解除跟随。现在只有按钮能关掉它，而且开启时按钮会亮起，所以被重新居中永远不会让你意外。

**就近优先。** 按与上次已知位置的距离重排撤离点列表；无论如何，每个撤离点都会显示自己的距离。撤离点标签页会显示全部，因为哪个阵营能用某个撤离点本来就写在各自那一行上，而一份和地图不一致的列表，比一份更长的列表更糟。如果你只玩一个阵营，设置里仍然有阵营筛选器。

**互相让位的名称。** 撤离点、任务、备注和队友的标签由同一趟排版统一放置，这一趟知道所有标签的情况，所以每个名字都会落在还没有别的名字占据的地方。先来先得：哪个图层先请求，就保留它想要的位置；其余的则向上、向下或挪到标记的另一侧，凡是挪得太远、可能让人分不清的，都会拉一根细线指回它标注的东西。地图美术里烧死的标签是本程序挪不动的，所以那些地方仍然可能被压住。

**刷新热力图。** 显示 PMC、Scav、AI PMC 和 Boss 可能出生的位置。半径以游戏内米数为单位，所以缩放改变的是你能看到多少，而不是数据本身；每一个色带都相对自身峰值缩放，这样一个稀疏的群体在密集群体旁边也依然看得见。

**其他图层。** 战利品容器、危险区域、上锁的门、开关、固定机枪、BTR 停靠点、Boss 区域和转移点，每一项都可以单独开关。图层和热力图位于浮在地图左下角的**图层**面板里，和**楼层**放在一起——地图上画什么本来就是地图本身的事，所以开关也就放在那里。

**截图清理。** 可选，且**默认关闭**。启用后，它只保留最新的 N 张截图，或者每张读完就删除。删除的文件会进回收站，绝不会删到监视文件夹之外，也绝不会碰任何不符合塔科夫截图命名规则的文件。

**全部 13 张地图。** 海关、工厂、中心区、破冰船、立交桥、实验室、迷宫、灯塔、储备站、海岸线、塔科夫街区、码头、森林。

**楼层切换，包括地面层。** 地图美术把各个楼层当成不透明几何体叠在一起，所以地下楼层被地面层挡在后面。把**地面层**关掉才能让它露出来——工厂的隧道就是最明显的例子。**楼层**控件浮在地图左上角，平时保持折叠，直到你需要它为止，因为大多数地图没什么可切的，而为了两个复选框放一整块侧边面板，太占窗口了。

**地图识别。** 从下拉菜单里选地图，或者让一个不可能出现在当前地图上的位置为你提供正确的那张。它只提议，不切换，因为好几张地图在世界坐标上互相重叠，而战局中途自动切错，比不给建议更糟。如果你更愿意，**设置**里也可以打开自动切换。

**设置，分六个分类。** **常规**（外观、语言、置顶、地图数据）、**截图与日志**、**地图显示**（视图、标记、撤离点、小地图）、**任务**、**联机**和**局域网同步**。本分支把原本十三个堆叠区块组成的一条长滚动条，换成了分类栏和每类一页，这也是局域网同步的开关能有地方安家的原因。改动会即时生效——没有确定，也没有取消——而且所有内容仍然可以在 `settings.json` 里手动编辑。

**它已经知道你接了哪些任务。** 打开游戏日志后，本程序会读取塔科夫写下的商人消息并一路跟进：接受任务就打勾，交付任务就取消勾选。任务 id 会随通知一起传来，所以这是精确的，而不是猜出来的。在开发机上，它第一次运行就从一周的日志里还原出 73 个进行中的任务。

它只知道日志保留下来的东西，所以一个在现存最老的日志之前接受的任务会显得从未动过——手动打勾依然有效，也绝不会因为日志什么都没说而被撤销。它推算出来的结果会被缓存，所以清空日志文件夹损失的是历史，而不是一切。

**从游戏同步**会丢掉手动挑选的列表，改为精确追踪日志中记录为已接受的任务。随着事件到来而跟进，无法修正一个已经跑偏的列表——一个在程序关闭时交付的任务永远不会产生事件来取消它的勾选——所以这就是那个“从游戏知道的状态重新开始”的按钮。**此处生效**会把列表筛选为游戏记录为已接受、且在你正看着的这张地图上有目标的任务，而这正是你在战局里会问的问题。

**把任务读清楚。** 点击任务名称，它会在左侧面板里打开：目标以你真正读得清的字号呈现，一个目标一块，每一块都说明它是否在你面前这张地图上，并各自带一个**路线**按钮。前置要求列出来，已完成的一项会打勾；钥匙按它们开锁所在的地图分组，*这张*地图用的那把排在最前；每个目标都会列出它需要的物品——带图片，而且包括它自己的措辞一带而过的替代品，因为“获取物品：Rye croutons”也同样接受 Emelya rye croutons。面板可以调整大小，也可以关闭。

**边做边勾掉目标。** 面板里每个目标都有自己的复选框；勾上的会在那里被划掉，它的标记也会完全从地图上撤下，于是画出来的就是还剩什么没做。这是本程序唯一一处用隐藏而不是变暗的地方——其他地方的含糊其辞，都是因为程序在猜；而一个勾，是你自己声明进度。塔科夫写下的任何日志都没有说你在一个任务里推进到了哪一步——通知日志会记录任务状态改变，但从不记录任务内部的条件——所以这只是一条写给自己的备忘，并且会以备忘的形式持久保存。**清除勾选**用于在新赛季重置某个任务。

**出发要带什么。** 在任务列表上方，任务标签页会统计你勾选的所有任务在你正看着的这张地图上需要什么：钥匙，以及你必须随身携带、而不是在柜台交出去的物品，并标明各自的数量。物品会跨任务累加，因为埋下一个就消耗一个；钥匙则从不累加，因为用一把钥匙并不消耗它。埋一个 MS2000 需要把标记器带在身上；上交五把 MP-133 并不意味着要带五把霰弹枪进海关，而这份列表分得清两者的区别。

**不用手输的等级。** 塔科夫没有把你的等级写进任何日志——查过十九个日志文件夹：没有经验值，没有升级行，而组队通知里虽然带着等级，但那是除你之外每个成员的等级。能确定的只有一个下界：一个要求 42 级的任务不可能在 41 级时被接受，所以日志里记录你接过的任务中，最高的那个要求，就是你至少已达到的等级。**根据日志**会应用它，而且只会往上调——估算落后于真实值，把你自己输入的数值往下拉，会隐藏你其实接得了的任务。在开发机上，它从一周的日志里读出 52。

**任务追踪。** **任务**标签页列出全部 510 个任务，按商人分组，带一个搜索框，以及对*这张地图上*、*不高于我的等级*和*Kappa* 的筛选。勾选一个，它的目标就会画到地图上：区域按其实际轮廓绘制，而不是一个点，所以一个“到访”目标读起来是*站进这个房间*，而不是*在这附近某处*。任务物品可能刷新在好几个地方时，每一处都是一个空心圆环，而不是一个确凿的标记——你总不该从四个旁边都走过去。

只有勾选的任务才会绘制，这是有意为之，而不是图省事：光灯塔一张图就有 169 个有具体位置的目标。勾选靠手动，因为你接受了哪些任务保存在 BSG 服务器上的你的个人资料里，而本程序读的是文件，不是账号。

在某个任务上按**路线**，或者点击它在地图上的某个标记，它的目标就会变成带编号的路线标记——也就是说它们会继承到达检测、引导线，以及以你的颜色分享给小队。没有具体位置的目标仍然会列在阅读面板里，因为“上交 5 把 MP-133”即使不在地图上，也值得放在地图旁边读一读。

**在地图上写字。** 按**添加备注**，点一个位置，输入。标签会保存到磁盘，并留在你写下它的那张地图上，于是你们小队真正在用的叫法——*Big Red*、*狙击手小屋*、*标记钥匙刷新的地方*——就落到了地图上，而不是留在每个人脑子里。点击你自己写的一条即可重命名，或者从**备注**标签页里删除。

**导入**是合并文件，而不是替换你的文件，所以有人给街区的每栋楼都标了名，也能把他的文件交给你，而不必牺牲你自己的。它能读本程序自己的导出格式，也能读纯 `map,x,z,text` 列表，因为几百个楼名的现实来源是一张电子表格，而不是手写的 JSON。

**把我的备注分享给小队**默认关闭，而且只发送你自己的备注。队友的备注以他们的颜色出现，绝不会写入你的文件，会话结束时就会消失——一套标签是几周里慢慢攒起来的，不是接下来十分钟的计划，而且在别人刚加入时就把你的标签塞到他们三个人的地图上，不是该不打招呼就做的事。

**还没截过一张图，地图就已经就位。** 在设置里勾选**读取游戏日志以判断正在加载哪张地图**，本程序就会跟随塔科夫运行时写下的日志。游戏在你获得操作权限前二十秒到两分钟就会写明它正在加载哪张地图，所以你一出生，第二块屏幕就已经显示正确的地图，地图切换也不再需要等你截一张图、并且恰好站在只有一张地图能包含的位置上。

它也知道战局何时开始，这比靠时钟的启发式判断更干净：你一获得操作权限，上一局的轨迹就立刻清掉，而不是等一两张截图之后。回到主菜单时什么都不会清除，因为事后回看打斗发生在哪里，正是人们用这张地图做的唯一一件事。

默认关闭，你一取消勾选，它就会立刻停止读取该文件。安装目录是从游戏记录在它自己的 Unity 日志里的路径找到的，即使装在第二块硬盘上、注册表里什么都没有也能奏效；如果这样还找不到，就自己设置文件夹。`--find-logs` 会打印试过的每一个位置、解析器对最新日志的解读，以及这个版本不认识的任何地点名——如果地图在某次补丁之后不再切换，这就是你该贴进 issue 的东西。

**小队位置。** **小队**面板浮在地图右上角，收起时是一个小药丸，直到你打开它。按**创建**，程序会给你一个类似 `K7QM4-3FHB9-8TZR9-M4X7Q` 的代码。任何人把它粘贴进**加入**，就会出现在你的地图上，而你也会出现在他们的地图上。大家可以在战局进行到一半时加入，并立刻拿到每个人的当前位置；如果出了岔子，你随时可以停止并重启一个会话。收起时，那个小药丸仍然显示你们有几个人；一旦有代码要复制，或者出了什么问题，它会自己打开。

**会承认自己已死的连接。** 两端每五秒交换一次心跳，某个链路静默二十一秒后就会被放弃。否则 TCP 会在一条早就停止传输任何东西的连接上继续挂着——路由器丢了映射、笔记本睡过去了、链路抖了一下——而两端都卡在阻塞读取里，以为小队一切正常。名单的每一行都会显示这次心跳的往返时间，所以某个队友的链路吃不动了，在他人掉线之前就能看出来。

**Shift 点击来标记。** 为整个小队标出一个位置，带脉冲、你的名字和一个倒计时。它持续 30 秒后自行清除，所以战局中途不用去收拾什么；它会发出声音，好让队友在看游戏、而不是看地图的时候也能注意到。圆环在这 30 秒里一直向外扩散，随时间推移渐渐平息，而不是戛然而止——一个标记对那个十五秒后才看地图、还得从另外三个里把它找出来的人最重要。如果你更愿意，可以在**设置**里关掉声音。标记在单人模式下也能用，作为一个会自行过期的临时记号。

只有和你处在同一张地图上时，队友才会被画出来——来自另一局的坐标在这一局的坐标系里没有任何意义。他们会留在名单里，并标注出他们实际所在的位置。每个标记还会带上自己的时间，并随时间变旧而变淡，因为队友只有截图时才会上报：一个一分钟前的点如果以满强度画出来，读起来就是“他现在就在那儿”，而你就会这样去相信一个根本没人守的角度。

每个队友都会留下一小段轨迹——默认五个位置，间隔拉开，好显示他们一直在往哪个方向移动，而不是每一步。当有人落在视野之外时，边缘的一个箭头会带着他们的名字和距离指向他们，这样你放大看自己那一角时，也不会跟丢其他人。位置已经彻底过时的队友一个箭头也不会有，因为执拗地指着某人三分钟前所在的位置，比什么都不说要糟。

**共享路线。** 你的路线标记会以你的颜色发给小队，而且每个图钉在*你*到达的瞬间就对所有人消失——别人的到达不影响它，所以没有什么需要商量的，也没有半径需要猜测。队友的路线比你自己的画得更小、更淡，只在第一个图钉处标一次名，而且它们**绝不**改变你的引导线方向，也不移动你的镜头。一个能让别人操纵你视角的功能，会是恶作剧工具，而不是便利。在**设置**里关掉它，这同时也会收回你已经分享出去的内容，而不是把它冻结在他们的地图上。

**每个人的颜色都是自己的。** 你挑的颜色会发给小队，而不是根据你在名单里的位置推算出来，所以每个客户端画出来的你都一样——包括你的标记。过去只要有人离开，两个客户端就可能对不上，而这正是颜色本该避免的混乱。

没有服务器。代码里包含房主的地址和一把共享密钥，所以小队直接相连，流量用一把别人都没有的密钥加密。所有人都拨向房主，这意味着只需要一个人能从自己的路由器外面被访问到——而且房主甚至不必在游戏里。

> **共享会话需要每个人都是 v0.8.0 或更新版本。** 颜色和路线改变了线路格式，密钥派生也随之变了，所以旧版本根本无法连接，而不是连上之后在战局中途失败。反正这连接注定要断，在门口就断是更厚道的那一半。

**如果非得转发端口**，那就只有一个：**`TCP 24601`，入站，转发到托管的那台电脑**。只有房主需要它；加入你的人什么端口都不用开。托管期间，面板会确切说明你从哪里可以被访问到——`Hosting on 203.0.113.4:24601 (TCP)`——当你的路由器不肯自行打开端口时，它会在悬停时变成琥珀色并显示转发详情。在你真正需要之前，**设置**里也有同一行信息。如果 24601 和别的东西冲突，可以在那里配置端口；而托管会拒绝启动，而不是悄悄换到另一个端口——一条钉在一个已经悄悄变了的数字上的转发规则，是最糟的一种坏。`--party-test` 会告诉你你属于哪种情况。

> **用之前值得想一想。** 位置共享保留了本程序“从不接触游戏”的性质，但它确实改变了谁知道什么。和自己的小队在一起，这很难让人反对——你本来就能在语音里说“我在宿舍”，而这只是更精确而已。但本程序分辨不出一个小队和一群正在协同的陌生人，因为它看不到游戏的组队系统。这个判断，它没法替你做。

**小地图。** 按**小地图**，会弹出一个小巧的置顶窗口，可以压在游戏本身上，适合你只有一块屏幕的时候。它画出主地图画的一切——你的位置和轨迹、撤离点、路线、小队、标记——范围以游戏内米数设置，而且它**始终**以你为中心。没有跟随开关：一个能被你平移开自己位置的小地图就只是一张小地图，而这个小地图的意义在于，瞥一眼就能回答“我周围有什么”，完全不需要任何操作。

它可以拖到任何地方，从角落调整大小，滚动改变范围，用标题栏里的滑块设置它的不透明度。**设置**里有一个点击穿透选项，让鼠标能够触到底下的游戏——它之所以放在那里而不是小地图上，是因为一旦打开，窗口就不可能被点击，包括任何本该把它重新关掉的按钮。

它终究只是一个窗口。没有任何东西被画进游戏里，没有任何东西被注入，它显示的也只是主窗口本来就有的内容。

**浅色和深色，字号看得清。** 全程等宽字体，带一个文字大小滑块，还有一个置顶开关，供它和别的东西共用屏幕时使用。

**你的标记，你的颜色。** 在**设置**里从十种命名颜色里挑选，并设置标记大小。同一个颜色就是小队看到的你，而且会话进行期间，取色器会标出别人已经在用的颜色——没有人会被拦着不让选，也没有人会被悄悄改掉，但提醒撞色最合适的时机，就是在你挑选的时候。

**在平板上，通过局域网。** 在**设置 → 局域网同步**里打开**通过局域网分享这张地图**，本程序就会把地图的只读副本提供给同一网络上的任何浏览器。平板看到的和桌面看到的一样——美术图、你的标记和它的轨迹、路线、引导线、撤离点、任务标记、备注、小队和标记——一秒之内就同步过去，并且可以用触摸平移和缩放。

它是镜像，仅此而已。上面每条路由都是只读：`GET /` 取页面，`/api/state` 取快照，`/map/{map}.svg` 和 `/tiles/…` 取美术图和它的切片（从桌面自己的缓存提供，而不是再取一遍），`/ws` 取实时流，而它只会订阅。没有任何一个端点会写入，所以浏览器连一件事都改不了，而且在你打开它之前，这一切都不会运行。

设置里显示地址、一个可扫描的**二维码**，以及一个**生成新链接**按钮。系统会为你生成一个八位访问令牌，除了页面本身，每个请求都必须带上它；没有带令牌——或者带错了——的请求会得到 **404**，所以网络之外的人甚至察觉不到这个服务的存在。重新生成令牌会立即生效，并切断所有还拿着旧链接的人。

它默认监听端口 8765，而且只在你的局域网内——它从不向互联网宣告自己，不在你的路由器上打开任何端口，也不改动任何端口映射——如果 8765 和别的东西冲突，端口可以配置。你第一次打开它时，Windows 可能会询问是否允许它通过你的**专用**网络；在你允许之前，它在来宾或公用网络上不会工作。

四个开关决定平板能看到什么：跟随玩家所在楼层、兴趣点、任务标记和备注。桌面上的东西本来就勾得很满时，在平板这边把相应项目关掉，是让一块小屏幕保持易读的常见做法。浏览器页面本身只有简体中文，无论桌面端设成什么语言。

**已知问题。** 两个，都写了下来，而不是掩盖过去：

- **撤离面板 OCR 只认英文。** 在中文游戏客户端里，撤离列表是中文的，但候选名称来自英文撤离点名称，所以**识别撤离点**什么也找不到。要修好它，就得先决定中文名称到底该怎么匹配，这也是它仍然悬而未决的原因——见 `docs/localization-ocr-chinese-backlog.md`。
- **渲染代价高昂。** 开启整套叠加层时，测得每帧 15–43 毫秒；只要一条路线有两个或更多路点，箭头动画就会整局跑一个 20 fps 的时钟。在老机器上这是实打实的开销，优先级排序的修复清单在 `docs/render-performance-backlog.md` 里。局域网同步不在其中。

## 首次运行

程序会在「文档」下查找 `Escape from Tarkov\Screenshots`，如果 OneDrive 迁移过你的「文档」文件夹，也会在 OneDrive 下找，并优先选用真正存有截图的那个。如果它仍然指错了地方，在**设置**里按**查找**，或者用**浏览**手动设置。文件夹下面那一行会说明它能看到多少张塔科夫截图——如果你在战局里截过图，那里却显示为零，说明游戏写到了别处，**查找**会把它找出来。从下拉菜单里选你的地图；如果一个位置落在当前地图不可能包含的地方，程序会提议切换。

全新安装默认简体中文。要换回英文，或者再换回来，用**设置 → 常规 → 语言**，程序会重启进入该语言。

## 从源码构建

需要 [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)。

```
git clone https://github.com/BlueMess/tarkov-map-companion-self-improv
cd tarkov-map-companion-self-improv
dotnet test              # 718 tests
Run.bat                  # or: dotnet run --project src/TarkovMapCompanion
```

要产出发布版所附的那个同样的单文件可执行程序：

```
scripts\publish.ps1
```

现在这个发布产物大约 62 MB，而不是 30 MB 左右，因为局域网同步带上了 ASP.NET Core 共享框架。它仍然落在 `publish\` 里，而该目录被 gitignore 了——所以每次改动之后，只要你想看到效果，就重新运行它，否则你会一直启动修复之前的那个二进制文件。

### 额外命令行模式

| 命令 | 作用 |
| --- | --- |
| `--render-test <map> [out.png] [w] [h] [floors] [nobase] [bare] [marks]` | 把一张地图渲染成 PNG，不开窗口。检查坐标改动的最快方式。`floors` 是逗号分隔的列表，`nobase` 隐藏地面层，`bare` 去掉标记，`marks` 在图上铺一条由路点组成的路线。 |
| `--fetch-data [out]` | 从 tarkov.dev 重新构建内置的兴趣点快照。 |
| `--fetch-tasks [out]` | 从 tarkov.dev 重新构建内置的任务快照。 |
| `--fetch-wiki [out]` | 从 EFT wiki 重新构建内置的撤离条件。 |
| `--find-screenshots` | 打印塔科夫截图可能存放的每一个位置，以及各自里面有什么。地图从不移动时该运行的东西。 |
| `--find-logs [folder] [all]` | 打印塔科夫自己的日志在哪里找到、解析器对最新日志的解读，以及这个版本不认识的任何地点名。地图不再切换时该运行的东西。`all` 会读取每次启动的日志，而不只是最新的那份。 |
| `--party-test [name] [local]` / `--party-test join <code> [name]` | 从控制台托管或加入一个位置共享会话。说明这个网络到底能不能托管，而这是唯一没法用别的方式测试的部分。`local` 使用回环地址，好让同一台机器上的两个进程互相通信。 |
| `--read-exits <screenshot.png> [map] [whole]` | 从一张截图里读出撤离面板，并打印每一个阶段：原始文本、它归并出的行，以及匹配到的撤离点。识别出错时该运行的东西。 |

没有局域网同步的命令行模式：WebSync 的开关和配置都在**设置**里，`--party-test` 也不会启动它。所提供页面自带一项自动化检查——`?selfcheck=1` 断言画布变换能经受一次旋转和一个虚线圆环——而对于一个测试套件本来就不碰的浏览器客户端来说，这点覆盖很单薄。

## 数据来源

地图美术、几何数据、撤离点、刷新点和战利品位置来自 [tarkov.dev](https://tarkov.dev) 社区项目——具体来说，几何数据来自 [`tarkov-dev`](https://github.com/the-hideout/tarkov-dev)（MIT），兴趣点数据来自 `json.tarkov.dev`。撤离*条件*不在这份数据里，而是取自[《逃离塔科夫》Wiki](https://escapefromtarkov.fandom.com)（CC BY-SA）。

物品图片来自 `assets.tarkov.dev`，每个物品一个文件，完全按物品的 BSG id 寻址——任务快照本来就带着它，所以没有索引需要下载，也没有需要保持同步的东西。它们会在某件物品第一次显示时被抓取，此后缓存在磁盘上；每张约 2.6 KB，整个快照引用到的所有物品加起来还不到一兆字节。关闭**从 tarkov.dev 下载地图图片与撤离点数据**后，名称照常显示，图片则不会。

地图作者在程序的「关于」界面里逐个致谢：**Shebuka**（10 张地图）、**Tarkov.dev**（实验室、迷宫）和 **TarkovBOT.eu**（破冰船）。

撤离条件由社区维护，可能落后于某个补丁。你可以创建 `%APPDATA%\TarkovMapCompanion\extract-notes.json`，不用重新构建就能修正它们；里面的条目会按撤离点覆盖内置的那份。它旁边的中文文件 `extract-notes.zh.json` 也以同样的方式覆盖中文内容。

撤离点、地图、兴趣点和物品*名称*的中文文本来自 tarkov.dev 自己的 `maps_zh` 载荷。撤离*条件*的中文不在这份数据里——wiki 没有官方翻译——所以它来自内置的 `Data/Snapshots/extract-notes.zh.json`，这个文件与英文文件并排放着，只在显示时对它做修饰，从不替换它。

那份上游载荷发布过一些让列表读不下去的缺陷，所以在构建列表时会修正其中三处：

- 地图上附着到**每一个**撤离点的某个开关 id 会被忽略，而不是变成所有撤离点上的条件、并让每一行都多出一条“开启方式”；
- 上游现在会把一个实际撤离点发成**两条位置重合的 `pmc` 和 `scav` 记录**，它会被折回一个通用撤离点，放在**撤离点：通用**图层里；而两个确实不同的同名撤离点则保持分开；
- 名称本身就是代码的撤离点（`ZB-1011`、`D-2`）在**每一种**语言里都保留该代码，即使中文表为其中两条记录之一提供了翻译也一样。

每一处都有 `PoiTests.cs` 里的测试覆盖，所以一次改变了数据形态的数据刷新会让构建失败，而不是悄悄把它们中的某一个重新引入。

| `%APPDATA%\TarkovMapCompanion\settings.json` | 你的偏好设置，包括你的语言、局域网同步开关及其访问令牌。可手动编辑。 |
| `%APPDATA%\TarkovMapCompanion\extract-notes.json` | 撤离条件的可选覆盖。 |
| `%APPDATA%\TarkovMapCompanion\extract-notes.zh.json` | 同上，中文版。 |
| `%LOCALAPPDATA%\TarkovMapCompanion\cache\` | 已下载的地图和切片。可以安全删除。 |
| `%LOCALAPPDATA%\TarkovMapCompanion\cache\icons\` | 物品图片，每个物品 id 一个。可以安全删除；需要时会重新回来。 |
| `%LOCALAPPDATA%\TarkovMapCompanion\cache\app.log` | 程序当时在做什么，包括它为什么停止。值得附在错误报告里。 |

局域网同步的访问令牌和其他偏好设置一起保存在 `settings.json` 里，服务器会实时读取它，而不是缓存它——所以**生成新链接**会立刻生效——并且提供桌面已经缓存的同一批地图和切片，而不是自己去取。

小队活动在两端都会用同一个从会话密钥派生出来的标签记录，形如 `[party ecb8932e host]`。两端各自算出同一个标签，谁都不用把它发出去，所以两个人的日志可以并排对齐——而标签对不上本身就是答案，因为它意味着有人粘贴了一个更旧的代码。地址在记录时会把最后一段掩掉，所以一份贴出来的日志不会泄露任何人的 IP。
